# What each lab's published system lets a sub-agent see

| Lab | System | What the sub-agent sees | Source | Verified |
|---|---|---|---|---|
| Anthropic | Claude Code subagents | Task message only. A non-fork subagent starts from a fresh context containing its own system prompt, the delegation prompt, CLAUDE.md files, a git status snapshot, preloaded skills and a sibling roster (names only, as SendMessage targets). It does not see the parent's conversation history or siblings' work; only its final result returns to the parent. Forks are the documented exception and inherit the entire conversation. ("Each subagent starts with a fresh, isolated context window.") | https://code.claude.com/docs/en/sub-agents | 2026-09-03T06:52:58Z |
| Anthropic | Multi-agent research system (Claude Research) | A task description written by the lead agent (objective, output format, tool and source guidance, task boundaries). Whether subagents see the parent conversation or each other is undocumented; the post describes them searching independently in parallel and returning findings to the lead. ("Each subagent needs an objective, an output format, guidance on the tools and sources to use, and clear task boundaries.") | https://www.anthropic.com/engineering/multi-agent-research-system | 2026-09-03T06:52:58Z |
| OpenAI | Agents SDK handoffs (and Swarm predecessor) | Shared transcript by default: on a handoff the receiving agent sees the entire previous conversation history; an input_filter can remove items (for example tool calls) before transfer. In the agents-as-tools pattern the manager passes an input and keeps control, and the docs do not state what conversation context the tool-agent receives. Swarm: system prompt changes on handoff, chat history does not. ("gets to see the entire previous conversation history") | https://openai.github.io/openai-agents-python/handoffs/ | 2026-09-03T06:52:58Z |
| OpenAI | Deep Research | Undocumented. The system card describes a single browsing model (early o3 variant) trained on browsing tasks and prompt-injection resistance; no sub-agent architecture or context policy is described. ("Deep research is a new agentic capability that conducts multi-step research on the internet for complex tasks.") | https://cdn.openai.com/deep-research-system-card.pdf | 2026-09-03T06:53:43Z |
| Google DeepMind / Google | Agent Development Kit (ADK 2.0) collaborative workflows | Mode-dependent. Task and single-turn mode subagents run in their own isolated session branch and cannot see peers; the parent receives the collected results. Chat-mode transfer (transfer_to_agent) hands the shared session to the target, and the state docs say a parent passes its InvocationContext to sub-agents so the chain shares the invocation id and temp state. An LlmAgent's include_contents defaults to receiving the relevant conversation history; 'none' makes it operate solely on its current instruction. ("each agent only sees events from its own branch when building context for AI model calls") | https://adk.dev/workflows/collaboration/ | 2026-09-03T06:59:50Z |
| Google | Gemini Deep Research | Undocumented. The launch post describes a user-approved multi-step research plan and iterative search; no sub-agent decomposition or context policy is published. ("creates a multi-step research plan for you to either revise or approve") | https://blog.google/products-and-platforms/products/gemini/google-gemini-deep-research/ | 2026-09-03T06:52:58Z |
| Meta | Muse Code (Muse Spark 1.2 / 1.3) | Task message only, as documented: the lead spawns a child for one bounded task and hands it that task; children share the lead's checkout unless worktree isolation is requested and can spawn grandchildren. Whether a child sees the parent's transcript or siblings is undocumented. Meta's Muse Spark 1.1 post frames the behaviour as trained: 'As a subagent, it adheres to its job, understands available tools, and knows when to escalate back to the main agent.' Session messaging is a separate peer-to-peer channel between independent sessions, each keeping its own transcript. ("A subagent is a child agent that the lead spawns for one bounded task.") | https://dev.meta.ai/docs/muse-code/extending.md | 2026-09-03T06:56:17Z |
| Microsoft | Agent Framework orchestrations (Handoff, Magentic, agent-as-tools); Magentic-One and AutoGen lineage | Pattern-dependent and explicitly documented. Handoff: the receiving agent has full context of what has been done so far (user and agent messages are broadcast to all participants; tool contents and handoff calls are not). Agent-as-tools: the primary agent manages context and might provide only relevant information to tool agents. Magentic: same architecture as group chat, so participants share the conversation and the manager's progress ledger supplies the instruction to the next speaker. ("The receiving agent has full context of what has been done so far.") | https://learn.microsoft.com/en-us/agent-framework/workflows/orchestrations/handoff | 2026-09-03T06:54:31Z |
| Thinking Machines Lab | None (no orchestrator-worker product); Defeating Nondeterminism post cited for methods | Undocumented. The lab publishes inference-determinism and fine-tuning work (Tinker) but no sub-agent system. | https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/ | 2026-09-03T06:52:58Z |
| xAI | Grok multi-agent model mode | Undocumented for the sub-agents themselves; the docs say multiple agents are launched to discuss the query and a leader synthesises. Sub-agent state is hidden from the caller and returned only encrypted when use_encrypted_content is set. ("Only the tool calls and final response from the leader agent are sent back to the user.") | https://docs.x.ai/developers/model-capabilities/text/multi-agent | 2026-09-03T06:52:58Z |
| DeepSeek | DeepSeek-V4 / DeepSeek-V3.2 (technical reports and API) | undocumented. Neither the V4 nor the V3.2 report describes an inference-time orchestrator-worker setup; the only multi-agent text concerns training-data synthesis, and the API exposes plain chat/function-calling with no sub-agent primitive. ("We employ a multi-agent pipeline based on DeepSeek-V3.2 to generate diverse, high-quality training data.") | https://arxiv.org/html/2512.02556v1 | 2026-09-03T06:59:26Z |
| Moonshot AI | Kimi K2.5 Agent Swarm (PARL) | Only its own subtask in a bounded local context: subtasks are 'semantically isolated', subagents keep independent working memories, do not read or write the orchestrator's global context, and no sibling visibility is described. The orchestrator receives only task-relevant outputs, not full traces. Roughly the paper's V0/V1 level. ("Long-horizon tasks are decomposed into parallel, semantically isolated subtasks, each executed by a specialized subagent with a bounded local context. Crucially, these subagents maintain independent working memories and perform local reasoning without directly mutating or contaminating the global context of the central orchestrator. Only task-relevant outputs—rather than full interaction traces—are selectively routed back to the orchestrator.") | https://arxiv.org/html/2602.02276v1 | 2026-09-03T06:58:37Z |
| Alibaba Qwen | Qwen Code subagents (regular and fork); Qwen-Agent GroupChat | Two documented settings. A regular named subagent keeps its own conversation history separate from the main chat and receives only the delegated task (V0-like). A fork subagent inherits the full parent conversation by default, or the most recent N real user turns via fork_turns (V2-like or beyond). In Qwen-Agent's GroupChat, each agent is handed the whole shared transcript with other agents' turns rewritten as attributed user messages. ("Have separate context - They maintain their own conversation history, separate from your main chat [...] Omitting it or using all inherits the full parent conversation. A positive integer string such as "3" inherits the most recent three real user turns.") | https://qwenlm.github.io/qwen-code-docs/en/users/features/sub-agents/ | 2026-09-03T06:58:38Z |
| Zhipu / Z.ai | GLM-5 / GLM-5.3 (technical report and developer docs) | undocumented. The GLM-5 report's 'orchestrator' is a training-time Multi-Task Rollout Orchestrator that schedules RL environments, not sub-agents; the GLM-5.3 docs mention research and judge agents only as environment builders. No statement of what a worker sees at inference. ("By decoupling inference and training engines via a central Multi-Task Rollout Orchestrator, we achieve high-throughput joint training across diverse agentic workloads.") | https://arxiv.org/html/2602.15763v1 | 2026-09-03T06:59:26Z |
| MiniMax | MiniMax-M2 series (Forge agent-native RL) | undocumented. The M2 report's MDP admits 'a communication with a sub-agent' as an action and names 'sub-agent delegation' as harness-level control flow, but specifies nothing about the sub-agent's observable context. ("This completion may contain natural language reasoning, a tool invocation request, an explicit context management operation, a communication with a sub-agent, or any combination thereof.") | https://arxiv.org/html/2605.26494v2 | 2026-09-03T06:59:26Z |
| ByteDance | DeerFlow 2.0 sub-agents (task() delegation); Seed-OSS | Only the task string passed through the task() tool, in an isolated context: the README states a sub-agent cannot see the main agent's context or other sub-agents (V0 as the shipped default). Seed-OSS itself documents tool use but no sub-agent policy. ("Isolated Sub-Agent Context: Each sub-agent runs in its own isolated context. This means that the sub-agent will not be able to see the context of the main agent or other sub-agents.") | https://raw.githubusercontent.com/bytedance/deer-flow/main/README.md | 2026-09-03T06:56:53Z |
| Tencent | Youtu-Agent OrchestraAgent (planner, workers, reporter); Hy3 | Every worker's prompt is built from the original problem, the full plan, the previous workers' trajectory, and its current subtask, so a worker sees the parent objective, every sibling's mandate and prior sibling outputs (comparable to the paper's V3 arm). Hy3 itself documents no sub-agent policy. ("TEMPLATE = r"""Original Problem:\n{problem}\n\nPlan:\n{plan}\n\nPrevious Trajectory:\n{trajectory}\n\nCurrent Task:\n{task}\n"""") | https://raw.githubusercontent.com/TencentCloudADP/youtu-agent/main/utu/agents/orchestra/worker.py | 2026-09-03T06:58:37Z |
